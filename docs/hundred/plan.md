# NYC 311 — 질문 100개 기획안

데이터: `data/processed/311_requests_clean.parquet` (2025-11-01 21:09 ~ 2026-10-31 21:09, 1년)
질문 목록: `docs/hundred/questions.json` (Q001~Q100, 모든 수치는 기획 단계에서 직접 계산해 `check_values`에 적어 둠)

## 공통 정의 (method 안의 약어)

| 약어 | 뜻 |
|---|---|
| **[B]** | 기준 데이터. `flag_system_duplicate == False` 인 행 전체(3,962,167행). 모든 질문의 출발점. `date` = `created_date`를 자정으로 내린 날짜 |
| **SA** | 슈퍼 신고 주소 `address_key == '655 EAST 230 STREET'`(브롱크스, 1년 47,105건, 99.8% 이웃 소음·앱). "SA 제외"라고 적힌 질문은 이 주소를 빼고 계산. `incident_address` 원문은 공백이 두 칸('EAST  230')이므로 반드시 `address_key`로 거른다 |
| **FULL** | 완전한 날 2025-11-02 ~ 2026-10-30 (363일). 첫날·마지막 날은 21시 무렵에서 잘려 있어 일 단위 평균/최대/최소에서 뺀다. 일별 집계는 건수 0인 날도 0으로 채운다(reindex) |
| **POP** | `docs/borough_context.csv`의 `population_census2020` (맨해튼 1,694,251 / 브루클린 2,736,074 / 퀸스 2,405,464 / 브롱크스 1,472,654 / SI 495,747). "1인당" = 건수 ÷ POP × 10만 |
| **TEMP 구간** | `data/external/nyc_daily_temp.json`의 `temperature_2m_mean`. 구간 [−∞,0), [0,10), [10,20), [20,25), [25,∞). FULL 363일 기준 날 수 59 / 90 / 89 / 86 / 39 |
| **NYPD 결과 분류** | `resolution_description` 문자열 포함 여부로, 위에서부터 먼저 맞는 것 하나: `issued a summons`→summons / `made an arrest`→arrest / `condition was corrected\|took action to fix`→corrected / `no evidence\|no criminal violation upon\|were gone`→noevidence / `police action was not necessary`→notnecessary / `unable to gain entry`→noentry / `observed an encampment\|referred the complaint to the Department of Homeless`→enc_found / `no encampment\|no Encampment`→enc_none / `jurisdiction`→notjuris / `report was prepared`→report / 빈 값→blank / 그 외→other |
| **처리시간 필터** | `is_closed & resolution_hours > 0 & ~flag_status_date_mismatch & ~flag_midnight_close` |

> 주의: NYPD의 가장 흔한 문장은 "…The condition was corrected **without the need to issue a summons** or effect an arrest…"다. 단순히 `summons` 단어로 찾으면 딱지 비율이 13%가 아니라 38%로 잘못 나온다. 반드시 `issued a summons` 구절로 찾는다.
> category형 컬럼의 `value_counts()`는 0건 범주가 섞여 나오므로 `> 0`만 쓴다.

## 책 전체 흐름

1. **워밍업(1~2장)**: 규모 → 달력. 숫자 하나로 바로 이해되는 질문으로 시작해 독자를 붙잡는다.
2. **바깥 세상(3~6장)**: 날씨 → 소음 → 동물 → 도로. 계절·시간·자치구 비교 그림이 번갈아 나오게 배치(막대·선·히트맵이 연속되지 않게).
3. **집 안(7장)**: 거리에서 집으로 시점을 옮긴다. 브롱크스·건물 쏠림이 다음 장의 '쏠림' 이야기로 이어진다.
4. **반전(8장)**: "그런데 이 통계, 몇몇 주소가 만든 거라면?" — 한 주소가 브롱크스 12월 소음을 4배로 부풀린 사례. 앞 장들에서 왜 'SA 제외'를 했는지 여기서 설명된다. (앞 장 본문에 "8장에서 다시 봅니다" 각주를 단다)
5. **신고 그 후(9~10장)**: 경찰·기관이 실제로 어떻게 답했는지. 8장의 SA 경찰 답변(Q069)이 9장으로 넘어가는 다리 역할.
6. **마무리(11~12장)**: 신고 방법과 별난 민원으로 가볍게 끝낸다.

## 데이터 품질 처리 원칙

- 모든 계산은 [B](`flag_system_duplicate` 제외)에서 시작.
- 소음·NYPD·채널·날씨 질문은 **SA 제외**(포함하면 브롱크스·겨울·앱 비중이 크게 왜곡). 주소 쏠림 장(8장)은 SA를 주인공으로 쓴다.
- 일 단위 평균/최대/최소는 FULL(363일)만.
- 처리시간은 처리시간 필터 적용(자정 일괄 종료 11.9만 건 제외).
- 자치구 비교는 반드시 POP로 정규화. borough 결측('Unspecified')은 전처리에서 이미 보정되어 없음(`borough_imputed` 265행).
- 개인 거주지일 수 있는 주소(Q060, Q065~Q072)는 책에 번지를 쓰지 않고 "브롱크스 230번가의 한 주소"처럼 쓴다.
